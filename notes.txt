你代码本身几乎是正确的。

红色下划线 不是运行错误，而是：

✅ TypeScript / VSCode 类型检查报错

⸻

✅ 为什么 menu 被红线？

你写的是：

const menu = document.getElementById('mobileMenu');
menu.classList.toggle('hidden');

但在 浏览器 DOM 类型定义里：

document.getElementById()

返回类型是：

HTMLElement | null

也就是说：

👉 menu 可能是 null

⸻

VSCode 的理解

它认为：

menu 可能不存在
↓
null 没有 classList
↓
报错

所以出现红色下划线。

⸻

✅ 正确写法（推荐 ⭐⭐⭐⭐⭐）

方法 1 —— Optional Chaining（最优）

btn?.addEventListener('click', () => {
  menu?.classList.toggle('hidden');
});

✔ 最安全
✔ 最现代
✔ Astro 官方推荐

⸻

方法 2 —— 类型断言（专业写法）

const menu = document.getElementById('mobileMenu') as HTMLElement;

然后：

menu.classList.toggle('hidden');

适合你 确定元素一定存在。

⸻

方法 3 —— 判空判断

if (menu) {
  menu.classList.toggle('hidden');
}

传统写法。

⸻

⭐ Astro 官方推荐版本（你应该用这个）

我帮你整理成 工业级 Navbar JS：

<script>
  const btn = document.getElementById('menuBtn');
  const menu = document.getElementById('mobileMenu');

  btn?.addEventListener('click', () => {
    menu?.classList.toggle('hidden');
  });
</script>


⸻

🚨 但这里还有一个 Astro 隐藏大坑

你现在的 script：

<script>

默认是：

build-time script（构建时执行）

❌ 浏览器不会执行！

⸻

✅ 正确写法（非常重要）

在 Astro 组件中：

<script is:inline>


⸻

✅ 最终正确版本

<script is:inline>
  const btn = document.getElementById('menuBtn');
  const menu = document.getElementById('mobileMenu');

  btn?.addEventListener('click', () => {
    menu?.classList.toggle('hidden');
  });
</script>


⸻

⭐ 为什么必须 is:inline

Astro 默认：

Script 类型	是否在浏览器运行
<script>	❌ 不运行
<script is:inline>	✅ 浏览器执行
<script client:load>	✅ Hydration

很多人 Navbar 点不开就是这里。
